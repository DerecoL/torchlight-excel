# 文件列表拖拽排序设计

## 背景

当前右侧文件列表按 `config.groups[activeGroupIndex].files` 数组顺序直接渲染。用户希望在当前分组内通过上下拖动文件卡片来自定义排序，并在下次打开应用时保持这个顺序。

本次设计仅覆盖右侧文件列表的拖拽排序，不修改左侧分组排序，不增加新的配置结构，也不调整导入导出协议。

## 目标

- 支持在当前分组内对文件卡片进行上下拖拽排序。
- 拖拽完成后立即保存到现有配置中。
- 重启应用后保持新的文件顺序。
- 不影响现有的打开、仅查看、删除、批量导入、导入导出逻辑。

## 非目标

- 不支持跨分组拖动文件。
- 不支持左侧分组拖动排序。
- 不引入第三方拖拽库。
- 不改动主进程、预加载层和配置文件结构。

## 方案对比

### 方案 A：原生 HTML5 拖拽

给每个 `.file-card` 增加 `draggable`，在渲染层处理 `dragstart`、`dragover`、`drop`、`dragend`，完成数组重排与保存。

优点：
- 无额外依赖，接入成本最低。
- 只需要改 `renderer/app.js` 与 `renderer/styles.css`。
- 与当前纯原生前端结构一致。

缺点：
- 默认拖拽反馈较弱，需要补充样式状态。
- 插入位置反馈需要自行处理。

### 方案 B：拖拽手柄

在卡片左侧或右侧增加单独手柄，仅通过手柄触发拖拽。

优点：
- 误触更少。
- 行为语义更明确。

缺点：
- 需要额外控件，打破当前卡片视觉结构。
- 交互多一步，不如整卡直观。

### 方案 C：第三方拖拽库

引入成熟的拖拽排序库完成占位、动画和排序逻辑。

优点：
- 默认交互与反馈更完整。
- 后续扩展能力更强。

缺点：
- 依赖与接入成本明显偏大。
- 对当前小型原生脚本项目属于过度设计。

## 结论

采用方案 A：原生 HTML5 拖拽，支持整张文件卡片直接上下拖动排序。

## 交互设计

- 用户按住任意文件卡片即可开始拖拽。
- 拖拽中的卡片显示半透明状态。
- 当前悬停目标卡片显示高亮和插入位置提示。
- 放手后立即完成排序、刷新列表并保存配置。
- 如果拖回原位，不执行重排和保存。
- 拖拽只在当前右侧文件列表内部生效，不接受外部拖入。

## 数据流设计

### 数据来源

文件列表继续基于 `config.groups[activeGroupIndex].files` 渲染，不新增任何排序字段。

### 排序流程

1. `dragstart` 时记录源索引。
2. `dragover` 时识别当前悬停卡片和鼠标相对位置。
3. `drop` 时计算最终插入索引。
4. 直接重排 `config.groups[activeGroupIndex].files`。
5. 调用现有 `window.configApi.save(config)` 立即持久化。
6. 重新执行 `renderFiles()`，必要时执行 `renderGroups()` 以保持界面状态一致。

### 持久化

顺序仍由 `files` 数组本身表达，因此现有导入、导出、分享逻辑天然兼容，无需调整配置 schema。

## 事件处理约束

- 拖拽事件只绑定在 `.file-card` 和 `#fileList` 范围内。
- 卡片内按钮点击仍按原逻辑执行，不应误触发排序。
- 当索引无效、分组不存在、文件数量不足 2 时，拖拽逻辑直接忽略。
- 当目标位置与源位置等价时，不进行保存。

## 错误处理

- 当 `activeGroupIndex` 无效时，不进入排序逻辑。
- 当 `group.files` 不存在或不是数组时，直接返回。
- 当 `drop` 没有有效目标时，仅清理拖拽状态，不报错。
- 无论拖拽成功与否，都在结束阶段清理高亮和插入提示，避免界面残留。

## 测试设计

### 手工验证

1. 在含有多个文件的分组中，把任意卡片从中间拖到顶部、底部和中间位置，确认视觉顺序正确。
2. 完成拖拽后关闭并重新打开应用，确认顺序保持不变。
3. 点击 `Checkout 并打开`、`仅查看`、删除按钮，确认原有功能仍正常且不会误触发拖拽。
4. 在空分组和单文件分组中确认无异常。
5. 把卡片拖回原位，确认没有多余保存和界面抖动。

## 风险与控制

### 风险 1：按钮点击与拖拽冲突

控制方式：避免在按钮区域上额外绑定拖拽事件；点击行为继续走现有按钮监听。

### 风险 2：拖拽反馈不明显

控制方式：通过拖拽中透明度、目标高亮和插入边界线提供明确反馈。

### 风险 3：保存时机不当导致频繁写配置

控制方式：只在有效 `drop` 且顺序发生变化时调用 `save(config)`。
